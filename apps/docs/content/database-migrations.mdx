# Database Migrations

A database migration is a script that changes the database schema in one step. Tikket uses migrations so that schema changes are stable and safe. If you change the schema in `schema.prisma` without a migration, the update can damage or delete all data in production. The system does not always know how to transform the data from the old schema to the new one. With migrations, each step is reproducible and transparent, and you can undo it.

To update the database, run one of these commands, as described on the [Upgrading](/upgrading) page. In a development environment, run:

```bash
yarn workspace @calcom/prisma db-migrate
```

In a production environment, run:

```bash
yarn workspace @calcom/prisma db-deploy
```

## Creating migrations

If you change the `schema.prisma` file, you must create a migration. To create the migration for your change, run:

```bash
yarn workspace @calcom/prisma db-migrate
```

The command asks for a short name that describes the change, for example `user_add_email_verified`. Then add and commit the migration together with the code that uses the new schema.

Always read the migration that Prisma generates. Prisma often drops whole columns of data when it cannot work out what to do.

## Error: The database schema is not empty

Prisma keeps a table named `_prisma_migrations` to track which migrations are applied. If the migrations in your local directory do not match the table in the database, Prisma stops with this error:

```
Error: P3005

The database schema for `localhost:5432` is not empty. Read more about how to baseline an existing production database: https://pris.ly/d/migrate-baseline
```

To correct the fault, tell Prisma which migrations are already applied. Run this command once for each migration, and replace `migration_name` with the name of that migration:

```bash
yarn prisma migrate resolve --applied migration_name
```

## Resetting Prisma migrate

If your local database is out of sync with the migrations, and the command above does not help, clear the migration table in PostgreSQL:

```sql
DELETE FROM "_prisma_migrations";
```

Then mark all migrations in the `prisma/migrations` directory as applied:

```bash
# Run the following to easily apply all migrations in the prisma/migrations directory
ls -1a prisma/migrations/ | grep 2021 | xargs -I{} prisma migrate resolve --applied {}
```
