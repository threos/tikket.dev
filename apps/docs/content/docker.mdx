# Docker

## Introduction

Tikket does not publish a Docker image. You build the image from this repository with Docker Compose. The `docker-compose.yml` file in the root of the repository references the upstream Cal.diy image by default. When you build the `calcom` service, Docker tags your build with that image name and uses your build instead of the upstream image.

## Docker files

The `Dockerfile` and `docker-compose.yml` in the root of the repository define the image and the stack. Read them if you want to customize your own image. To change the Docker configuration for everyone, open an issue or a pull request at https://github.com/threos/tikket.dev.

## Requirements

Make sure that `docker` and `docker compose` are installed on the server. Use `docker compose` without the hyphen. The Docker documentation names it as the primary form of docker-compose.

## Build the image

1. Clone the repository:

   ```bash
   git clone https://github.com/threos/tikket.dev.git
   ```

2. Go into the new directory:

   ```bash
   cd tikket.dev
   ```

3. Create the configuration file. Copy `.env.example` to `.env` and then edit `.env`. Most values can stay as they are. The Configuration section below lists the variables that matter.

   ```bash
   cp .env.example .env
   ```

4. Make sure that a database is available during the build. The build needs one. If your database runs elsewhere, set `DATABASE_URL` in `.env` and skip the next command. If not, start a local database with Docker Compose:

   ```bash
   docker compose up -d database
   ```

5. Build the image. The `DOCKER_BUILDKIT=0` setting lets the build use a network bridge:

   ```bash
   DOCKER_BUILDKIT=0 docker compose build calcom
   ```

## Start Tikket

Start the services that fit your setup. The complete stack includes a local Postgres database, the Tikket web app and Prisma Studio. Prisma Studio is a web UI that shows the content of the database.

To run the complete stack:

```bash
docker compose up -d
```

To run the Tikket web app and Prisma Studio against a remote database, set `DATABASE_URL` to that database in `.env` and run:

```bash
docker compose up -d calcom studio
```

To run only the Tikket web app against a remote database, set `DATABASE_URL` in `.env` and run:

```bash
docker compose up -d calcom
```

Then open http://localhost:3000, or the URL that you set as `NEXT_PUBLIC_WEBAPP_URL`, in a browser. On the first run, a setup wizard opens. Create your first user in the wizard.

## Update the instance

1. Stop the stack:

   ```bash
   docker compose down
   ```

2. Pull the latest code:

   ```bash
   git pull
   ```

3. Build the image again:

   ```bash
   DOCKER_BUILDKIT=0 docker compose build calcom
   ```

4. If the new version adds environment variables, add them to `.env`.

5. Start the stack again:

   ```bash
   docker compose up -d
   ```

## Configuration

### Build-time variables

Docker reads these variables from the `.env` file when it builds the image. You do not have to change them for a test setup. For production, you can need other values. If you change one of these variables, build the image again:

- `NEXT_PUBLIC_TELEMETRY_KEY`
- `NEXT_PUBLIC_LICENSE_CONSENT`
- `NEXT_PUBLIC_WEBAPP_URL`

### Run-time variables

The important run-time variable is `NEXTAUTH_SECRET`. Set it in `.env` before you start the stack. The [Installation](/installation) page shows how to generate it.

## Troubleshooting

The [Troubleshooting](/troubleshooting) page covers more faults, including the API v2 service and reverse proxies.

### Failed to commit changes: Invalid `prisma.user.create()`

Some versions cannot create a user when the `metadata` field is empty. Set the field to an empty JSON object, `{}`. The `id` field auto-increments, so you can also leave `id` empty.

### SSL edge termination

If a load balancer in front of Tikket handles the SSL certificates, add the environment variable `NODE_TLS_REJECT_UNAUTHORIZED=0`. Without it, Tikket rejects the requests. Only do this if you trust every service and load balancer that sends traffic to Tikket. The variable turns off TLS certificate verification.

### CLIENT_FETCH_ERROR

The default Auth callback on the server uses `WEBAPP_URL` as its base URL. The container does not always have the same DNS as your local machine, so it cannot resolve that URL. To correct the fault, configure `NEXTAUTH_URL=http://localhost:3000/api/auth`. The backend then connects back to itself.

```
docker-calcom-1  | @calcom/web:start: [next-auth][error][CLIENT_FETCH_ERROR]
docker-calcom-1  | @calcom/web:start: https://next-auth.js.org/errors#client_fetch_error request to http://testing.localhost:3000/api/auth/session failed, reason: getaddrinfo ENOTFOUND testing.localhost
```
