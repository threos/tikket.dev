# Installation

You can deploy Tikket in several ways. This page covers the production build from source, cron jobs, the API server and one-click deployments. The `README.md` file in the root of the repository covers the development setup.

## Requirements

Tikket needs little hardware while it runs. The build is the step that needs the most CPU and memory.

Tikket runs on Windows, Mac, Linux and BSD, because it only needs a JavaScript runtime. Any operating system that runs Node.js can work. For production deployments, use Linux.

Install these tools before you continue:

- Node.js 18 or newer
- Yarn 4
- Git
- PostgreSQL 13 or newer

Tikket uses Prisma for database maintenance. Prisma is a dependency, and `yarn` installs it with the other dependencies. Each tool has its own installation guide. On Linux or BSD, your package manager has all of them. For example, search the web for "Debian 12 PostgreSQL" to find a guide for PostgreSQL on Debian 12.

## Production Build

1. Clone the repository to get a copy of the code:

   ```bash
   git clone https://github.com/threos/tikket.dev.git
   ```

   If you are on Windows, open the terminal with admin privileges and clone with this command instead:

   ```bash
   git clone -c core.symlinks=true https://github.com/threos/tikket.dev.git
   ```

2. Go into the new directory:

   ```bash
   cd tikket.dev
   ```

3. Install the dependencies. A dependency is a package that Tikket needs to run.

   ```bash
   yarn
   ```

4. Create the configuration file. Copy `.env.example` to `.env`. The file has a comment for each variable that you can set.

   ```bash
   cp .env.example .env
   ```

   For preview deployments on Vercel, leave these variables empty:

   - `NEXTAUTH_URL`
   - `NEXT_PUBLIC_WEBSITE_URL`
   - `NEXT_PUBLIC_WEBAPP_URL`

5. Generate a secret and add it as `NEXTAUTH_SECRET` in the `.env` file. You can use another secret generator instead of `openssl`.

   ```bash
   openssl rand -base64 32
   ```

6. Copy `.env.appStore.example` to `.env.appStore` and fill it out in the same way. This file holds the keys that enable apps.

7. If you upgrade from an earlier version, update the database before you build. The [Upgrading](/upgrading) page has the commands. For a production build, also set up [E2E testing](https://github.com/threos/tikket.dev#e2e-testing).

8. Build and start Tikket:

   ```bash
   yarn build
   yarn start
   ```

## Cron Jobs

Some features need cron jobs. A cron job is a command that runs on a schedule. When you self-host, set up the cron jobs with the tool of your hosting platform. For example, on Vercel follow [this guide](https://vercel.com/guides/how-to-setup-cron-jobs).

The cron handlers are in this directory of the repository:

```
/apps/web/app/api/cron
```

## App store seeder

Tikket has a seeder script for app store apps. The admin UI wizard is the better way to enable apps. Use the wizard instead of the seeder.

## API

1. Copy the `.env` files from their example files:

   ```bash
   cp apps/api/v2/.env.example apps/api/v2/.env
   cp .env.example .env
   ```

2. Install the packages:

   ```bash
   yarn
   ```

3. Build and run API v2:

   ```bash
   yarn workspace @calcom/api-v2 build
   yarn workspace @calcom/api-v2 start
   ```

## Other environments

Tikket is a Next.js application. Any guide for Next.js applications applies to Tikket. For example, Netlify is similar to Vercel and supports Next.js. To deploy on Netlify, read the Netlify docs for Next.js projects. On a self-hosted server, you can also add a reverse proxy or an SSL gateway. We cannot support every configuration. If you want to deploy Tikket with a given tool, read the docs of that tool for Next.js applications.
